# KANSOKU v0.7: packet and flow observation

## Scope

v0.7 introduces the first packet-level observation module. It does not yet recommend router, switch, or firewall configuration. Its responsibility is to acquire bounded evidence and convert it into a stable, vendor-neutral observation model for later diagnosis and configuration analysis.

## Privacy-first capture policy

1. Live capture defaults to a 96-byte snaplen.
2. BPF filtering is supported and should be as narrow as the diagnosis allows.
3. Full-packet capture requires the explicit `--full-packet` flag.
4. Raw pcap remains local or edge-local.
5. Remote ingest carries only capture provenance, summary observations, and bounded aggregated flows.
6. Retention and quota enforcement are available independently of database metadata retention.

## Supported classic-pcap link types

- Ethernet (`DLT_EN10MB`), including 802.1Q/QinQ parsing;
- BSD/macOS loopback (`DLT_NULL`, `DLT_LOOP`);
- Linux cooked capture (`DLT_LINUX_SLL`);
- raw IPv4/IPv6 (`DLT_RAW`).

v0.7 intentionally rejects pcapng so unsupported parsing cannot silently produce misleading flow records.

## Extracted protocol metadata

- IPv4 and IPv6 endpoints;
- TCP, UDP, SCTP ports;
- ICMP/ICMPv6 and selected protocol names;
- TCP flag counts;
- VLAN ID;
- captured and original wire lengths;
- first/last timestamps;
- directional 5-tuple flow aggregates.

## CLI overview

```text
capture interfaces
capture run
capture summarize
  - idempotent by target, source, and SHA-256
  - `--force-reimport` explicitly creates another capture session
capture list
capture show
capture flows
capture prune
edge pcap
edge capture
```

## Safety boundary

Packet capture can contain personal or confidential communication metadata and, in full-packet mode, application payload. KANSOKU v0.7 provides technical minimization controls but does not replace organizational authorization, consent, legal review, access control, or incident-response procedures.

## State evaluation boundary

Capture-count and flow-summary observations are not interpreted as path health in v0.7. The ingest API skips automatic state estimation for pcap-only batches, preventing metadata-only captures from being mislabeled `NORMAL`. Ping, loss, throughput, reachability, and retransmission observations continue to trigger the existing state engine.
