# KANSOKU v0.5 design

## Goal

Move from manual target-by-target commands to a persistent multi-target observation service without weakening the v0.4 safety boundary.

## Core decisions

1. Target inventory is stored in SQLite and is separate from evaluation profiles and safety policies.
2. Scheduling uses the active observation plan so verified observation-rate actions affect subsequent cycles.
3. iperf3 cadence is configurable independently of ping to limit measurement load.
4. Every service attempt creates a scheduler-cycle audit record.
5. A database lease prevents duplicate service instances.
6. Automatic control is limited to low-risk proposals and never enables system-changing adapters.
7. The dashboard remains read-only.

## Non-goals

- OS service installation (`launchd` or `systemd`) is not automated in v0.5.
- Distributed scheduling across multiple Hub databases is not implemented.
- Real route switching remains site-specific.
- Credentials and remote command execution are not stored in the target inventory.
