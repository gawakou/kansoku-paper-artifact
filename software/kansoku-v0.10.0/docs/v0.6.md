# KANSOKU v0.6 design

## Goal

v0.6 separates observation execution from the central Hub. An edge node may continue collecting during a Hub outage and later deliver the same immutable batch without duplication.

## Trust model

The Hub operator explicitly registers each agent and issues a one-time token. The token is never stored in plaintext by the Hub. An authenticated agent may submit observation evidence and heartbeat data, but it cannot change Safety Policies, approvals, observation plans, or system-control permissions through the ingest API.

## Delivery model

1. The edge collector creates an `IngestBatch`.
2. The batch is atomically written to a local owner-only spool.
3. The edge attempts FIFO delivery.
4. The Hub authenticates the agent and checks `batch_id`.
5. A new batch is persisted and receives an `IngestReceipt`.
6. A repeated batch receives `DUPLICATE` without duplicate observations.
7. The edge removes the spool file only after an accepted or duplicate receipt.

## API

- `GET /health`
- `POST /api/v1/heartbeat`
- `POST /api/v1/ingest`

Authenticated requests require:

```text
Authorization: Bearer <agent token>
X-KANSOKU-Agent: <agent_id>
Content-Type: application/json
```

## New persistent entities

- `RemoteAgentRegistration`
- `AgentHeartbeat`
- `IngestBatch`
- `IngestReceipt`

## Non-goals

v0.6 does not implement TLS termination, remote command execution, automatic agent software update, or distributed consensus. These remain future work.
